# Lane Warden P2-0.15.2 — Living Lanes Input Patch

## Why this patch exists

The first Living Lanes release made the battlefield spatial, but its input layer accidentally removed two important freedoms:

1. A Commander already crossing the junction could not be redirected until travel completed.
2. The Living Lanes renderer compressed the full lane into the viewport and intercepted the old camera gestures, so the battlefield could no longer be panned around.

Both behaviors were contrary to the intended spatial-control model.

## Commander retargeting

- Same-lane tap-to-move continues to replace the current destination from the Warden's present position.
- During cross-lane travel, tapping another position in the current destination lane updates the destination without waiting for arrival.
- Tapping back toward the origin lane reverses the cross-lane trip using the current travel progress.
- A reversed trip returns along the existing path first, then completes any newly requested same-lane movement.
- Lane-card WALK controls use the same retargeting behavior.

## Battlefield camera

Living Lanes again uses a battlefield wider than the viewport rather than fitting the entire lane onscreen.

- Tap: move / retarget the Warden.
- One-finger drag: pan horizontally.
- Pinch: zoom.
- Recenter button: center the Living Lanes camera on the Warden.
- Lane-card selection: focus the Living Lanes camera on that lane's active friendly line.
- Drag and pinch gestures do not issue accidental movement orders.

## Display cleanup

- Battle HUD build marker now reports `0.15.2` instead of the stale `0.12.0` label left by the older UI patch.
- Home-shell and updater diagnostics report P2-0.15.2.

## Preserved systems

No reward, encounter, unit, tower, or battle-balance tuning was intentionally changed in this patch.
