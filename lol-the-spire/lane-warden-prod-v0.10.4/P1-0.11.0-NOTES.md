# Lane Warden — P1-0.11.0 First Production Battle

**Status:** ACTIVE HUMAN-TUNING BUILD  
**Design baseline:** 1.7  
**Stable install scope:** `/lol-the-spire/lane-warden-prod-v0.10.4/`

## What changed from P0

P1 turns Outer Approach from a functional rules sketch into the first production battle slice.

Implemented:

- Act 1 two-lane / no-Rival structure;
- legal 6 Unit-point / 4 Tower-point deployment budget;
- starting unit and tower reference costs;
- player-edited lane composition and tower choice/slot;
- deployment legality enforcement before Start;
- battlefield wider than the viewport;
- one-finger camera pan and bounded pinch zoom;
- lane-strip taps focus camera only;
- persistent Commander recenter;
- visible authored junction;
- normal Commander lane changes use timed junction travel;
- Waypoint uses an explicit lane target and relocates instantly;
- Commander health, endangered state, incapacitation, and timed reform;
- recurring lane pulses instead of one static army dump;
- Presence-linked local battle value;
- player Bastions protect the Core; enemy Guards protect Gate access;
- permanent Gate-vulnerability latch after the first Guard break;
- exposed Gate requires continued lane pressure / Sunder to destroy;
- selected-lane tower controls;
- tower Fortify and Overcharge battle-gold sinks;
- Reinforce adds pressure to the next two pulses without rewriting deployment;
- Reclamation countdown and phase announcement;
- Reclamation Gate artillery with lane telegraph;
- Reclamation Guard rebuild without Gate re-shielding;
- Reclamation abandoned-lane pressure escalation;
- normal victory, payable Last Stand, terminal Last Stand;
- automatic in-progress battle recovery snapshot every ~2 simulation seconds;
- self-updating PWA remains the delivery path.

## Important corrected P0 shortcut

P0 partially inverted objective responsibilities in its simplified pressure model. P1 corrects the rule direction:

- friendly pressure advances toward enemy Guards and the Gate;
- enemy pressure retreats the front toward player Bastions;
- a player Bastion must be broken before that lane can threaten the shared Core;
- a Guard is an enemy defense and is not shielded by the player's Bastion.

## Reclamation tuning values in this build

These are implementation hypotheses, not design invariants:

- trigger: 180 seconds;
- artillery cadence: 14 seconds;
- artillery telegraph: 4 seconds;
- Guard rebuild cadence: 28 seconds.

## Human-use questions for this build

Do not treat these as pass/fail gates yet. Observe:

1. Can the player form a deployment thesis with 6/4 capacity rather than merely fill points?
2. Does walking versus Waypoint feel qualitatively different?
3. Does battle gold create a real fork between stabilizing a tower and reinforcing the offensive lane?
4. Can the player explain whether a Guard is making net progress or regenerating?
5. Does Gate vulnerability create a satisfying second phase instead of an automatic win?
6. If Reclamation appears, is every new pressure attributable to Reclamation?
7. Does the finite protected-reading reserve feel helpful, stressful, exploitable, or invisible?

P1 remains a production build, not a standalone test harness. Numerical findings should feed normal production tuning unless a genuinely unresolved design risk requires a focused experiment.
