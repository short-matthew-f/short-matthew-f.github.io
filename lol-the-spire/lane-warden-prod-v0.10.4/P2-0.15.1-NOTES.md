# Lane Warden P2-0.15.1 — Mixed-shell recovery hotfix

Observed on iPhone Safari after the P2-0.15.0 Living Lanes release: the static home HTML remained P2-0.14.0 while `updater.js`, `build.json`, and the controlling service worker had advanced to P2-0.15.0. Because the stale HTML did not reference `living-lanes.js` or `living-ui.js`, the diagnostic line could report 0.15 while the player was still running the old battlefield shell.

## Fix

- `index.html` now carries an explicit `lw-shell-build` marker.
- `updater.js` reports APP / SHELL / LATEST / SW independently.
- When scripts and advertised build are current but the HTML shell is stale, the updater fetches a cache-busted `index.html`, verifies the shell marker and Living Lanes script references, and only then navigates to it.
- If GitHub Pages has not propagated the fresh shell yet, the updater waits and retries rather than entering a reload loop.
- Active battles are not forcibly reloaded; shell repair waits until the player is outside battle.
- The service worker rejects installation when its fetched `index.html` does not match its own build marker, preventing a new worker from permanently precaching an old shell.
- Navigation handling attempts a cache-busted current shell before falling back.
- Reward UI invariant label now uses the active application build instead of the old hard-coded P2-0.13.0 label.
- Split Causeway deployment copy now describes the Living Lanes encounter rather than the old reward proving-ground placeholder.

No Living Lanes combat tuning changed in this hotfix.
