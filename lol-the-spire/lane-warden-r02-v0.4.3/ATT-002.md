# ATT-002 — Severity Attention Badge

## Problem

R02-C preserved ATT-001's no-camera-seizure behavior, but the upper-left world-locked threat affordance was visually weak and difficult to tap on iPhone. Human feedback described it as basically impossible to see or click.

## Goal

Keep the attention contract:

`toast + edge/onscreen marker + tap-to-focus; no automatic camera seizure`

while making the marker discoverable, tappable, and urgency-bearing.

## Interaction

The marker is now a small circular `!` with a larger invisible hit target.

- visible circle: 30 px
- hit target: 48 × 48 px
- upper-left safe-area inset
- tap focuses the currently threatened lane
- tapping does not move the Commander
- tapping does not automatically issue any gameplay command
- pulse briefly pauses after acknowledgement

## Severity ladder

| Level | Color | Motion | Intended meaning |
| --- | --- | --- | --- |
| Info | Grey | none | Worth noticing; no immediate danger |
| Watch | Yellow | slow pulse | Emerging risk |
| Urgent | Orange | medium-fast pulse | Decision pressure now |
| Critical | Red | fastest pulse | Immediate consequence / loss state |

Current exploratory event mapping:

- Info: Waypoint/reform-selection confirmations.
- Watch: first Bastion warning and default warning-class attention.
- Urgent: Bastion critical, Commander endangered, Guard breach open.
- Critical: Bastion lost, Commander incapacitated, Core-level consequence.

## Accessibility

- 48 px target exceeds the 44 px minimum interaction target used elsewhere in the project.
- Alert meaning is not color-only: the same `!` shape is always present and pulse speed provides a secondary urgency cue.
- `prefers-reduced-motion` disables pulsing.
- Dynamic ARIA label names the event and target lane.

## Telemetry

R02-D exports:

- `structuralClaims.attentionSeverityBadge = true`
- `attention-shown` with `lane`, `severity`, and `title`
- `attention-focus` with the severity that was tapped

## Status

Exploratory UI patch. Formal smallest-supported-iPhone readability/tap acceptance remains future work.
